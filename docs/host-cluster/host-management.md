在 Web UI 的 **主机管理** 中登记一台机器，再到这台机器上安装 `stx-agent`。主机显示在线后，才能在上面发现进程、安装集群或执行启停操作。当前可用的类型是 **物理机 / 虚拟机**；Docker 和 Kubernetes 类型尚未适配。

## 添加主机

Web UI：**主机管理** → **创建主机**。列表可按在线 / 未安装 / 离线筛选，并查看 CPU、内存：

![主机管理列表](/img/screenshots/03-hosts.png)

| 字段 | 说明 |
| :--- | :--- |
| **名称** | 必填，全局唯一 |
| **类型** | 选物理机 / 虚拟机（默认） |
| **IP** | 必填，合法 IPv4 / IPv6；同 IP 不可重复 |

创建后先显示未安装。还要在这台机器上运行安装引导里的命令，等待它连接 STX Server。

## 安装 stx-agent

打开主机详情中的安装引导，复制生成的命令到被纳管主机执行。假设 STX 安装机是 `10.0.0.10`，命令中的下载地址应是这台机器能访问的 `http://10.0.0.10:17800`。命令形式如下：

```bash
curl -sSL http://10.0.0.10:17800/api/v1/agent/install.sh \
  | bash -s -- --install-dir=$HOME/.stx/agent/ --host-id <id>
```

要点：

- 默认安装目录 `$HOME/.stx/agent/`，可改；`--host-id` 与主机记录绑定
- 该主机需能访问 STX 安装机上的 **API（默认 17800）** 与 **gRPC（默认 17890）**
- 安装脚本、二进制、证书等由 STX Server 统一提供

装完后回到引导页等待状态变为在线。`stx-agent` 默认每 **10 秒**发一次心跳，超过 **30 秒**没有上报会显示离线。

:::tip
如果安装命令里出现 `localhost:17800`，而被纳管主机不是 STX 安装机，请先检查 `app.external_url`。安装命令必须能从被纳管主机访问。
:::

## 主机状态与关联规则

注册时 STX Server 按顺序匹配：

1. 安装命令里的 **显式主机 ID**
2. 上报主 IP 与已登记主机 IP
3. 同名且尚未安装 Agent 的主机
4. 仍无匹配 → **自动创建**一台物理机 / 虚拟机主机

登记时填错 IP：若该 IP 不在 Agent 本机地址集合中，STX Server 会用上报主 IP 校正。

未带主机 ID、仅靠 IP / 主机名发现时，也按这套顺序处理。STX Server 重启后会忽略重启前的旧心跳。

## 常见限制

| 场景 | 行为 |
| :--- | :--- |
| 名称 / IP 冲突 | 创建、更新会被拒绝 |
| 主机仍挂在集群节点上 | **不可删除**，需先从集群移除节点 |
| Agent 断线再上线 | 心跳恢复后重新标为已安装，资源指标继续刷新 |

## 与集群的关系

- 主机在线后，可在该主机上 **发现 SeaTunnel 进程** 或走 **一键安装**
- 集群节点关联到主机；启停、日志、预检都经该主机上的 Agent 执行

下一步见 [集群管理](./cluster-management)。
