主机管理

主机是 STX 里「能跑 SeaTunnel 的机器」，也就是架构里说的 被纳管主机。当前这一版正式可用的是 物理机 / 虚拟机：在 Web UI 登记主机 → 在该机器上安装 stx-agent → Agent 注册与心跳。Docker / Kubernetes 环境类型已预留，尚未适配。

生命周期​

阶段含义
登记Web UI / API 已有主机记录，Agent 尚未接入
安装 Agent复制安装命令到该主机执行（命令带主机 ID，预绑定）
注册成功Agent 已接入，写入系统信息（OS、架构、CPU、内存、磁盘等）
在线心跳正常，可做发现进程、安装、启停等操作
离线超过心跳超时未上报

在线判定：

  • 默认心跳间隔 10s，超时 30s 判离线
  • STX Server 重启后，会忽略重启前的旧心跳，避免假在线

添加主机​

Web UI：主机管理 → 创建主机。列表可按在线 / 未安装 / 离线筛选，并查看 CPU、内存：

字段说明
名称必填，全局唯一
类型选物理机 / 虚拟机（默认）
IP必填，合法 IPv4 / IPv6；同 IP 不可重复

创建后主机仍处于待接入状态。真正「纳管」发生在 Agent 连上之后。

CLI 等价：

stx host create --name node-1 --ip-address 192.0.2.10 --confirm

安装 Agent​

在主机详情或安装引导里取一键命令，形如：

curl -sSL http://<STX-Server>:17800/api/v1/agent/install.sh \
  | bash -s -- --install-dir=$HOME/.stx/agent/ --host-id <id>

要点：

  • 默认安装目录 $HOME/.stx/agent/，可改；--host-id 与主机记录绑定
  • 该主机需能访问 STX 安装机上的 API（默认 17800） 与 gRPC（默认 17890）
  • 安装脚本、二进制、证书等由 STX Server 统一提供

装完后引导页会轮询主机状态；显示为在线即表示握手成功。

Agent 如何绑到主机​

注册时 STX Server 按顺序匹配：

  1. 安装命令里的 显式主机 ID
  2. 上报主 IP 与已登记主机 IP
  3. 同名且尚未安装 Agent 的主机
  4. 仍无匹配 → 自动创建一台物理机 / 虚拟机主机

用户填错 IP 时：若该 IP 不在 Agent 本机地址集合中，STX Server 会用上报主 IP 校正。

未带主机 ID、仅靠 IP / 主机名自动发现时，也走同一套规则。

状态与常见约束​

场景行为
名称 / IP 冲突创建、更新会被拒绝
主机仍挂在集群节点上不可删除，需先从集群移除节点
Agent 断线再上线心跳恢复后重新标为已安装，资源指标继续刷新

与集群的关系​

  • 主机在线后，可在该主机上 发现 SeaTunnel 进程 或走 一键安装
  • 集群节点关联到主机；启停、日志、预检都经该主机上的 Agent 执行
