Web UI **安装包与插件** → **安装包管理**（`/packages`）。这里存放的是 **SeaTunnel 发行包**（`.tar.gz`），不是 STX 自身安装包，也不是连接器 JAR（连接器见[插件市场](./plugin-marketplace)）。

![安装包管理：在线版本与下载入口](/img/screenshots/24-packages.png)

包先保存在运行 **STX Server** 的机器上，再在一键安装或升级时经 **stx-agent** 推到被纳管主机。

## 为什么需要离线导入 / 导出

**安装包管理**拉发行版、**插件市场**拉连接器，日常都要能访问外网镜像；STX 安装机断网后，这两页没法正常下载。

页头提供统一入口 **离线导入 / 导出**：

| Tab | 做什么 |
| :--- | :--- |
| **导入** | 按文件名自动识别：离线资产包，或单个官方 `*-bin.tar.gz` |
| **导出** | 把本机本地仓已有的安装包（± 插件）打成 `stx-seatunnel-offline-*.tar.gz` |

需要同时上传源码包或自定义版本号时，在导入 Tab 打开 **完整上传表单**（原「上传安装包」）。

注意：无网环境还要另备 **STX 离线安装包** 来装控制面本身（见[离线安装](../get-started/quick-start#离线安装)）。STX 安装包和 SeaTunnel 资产包是两回事，不能互相替代。

## 在线版本与本地安装包

页内可切换两个列表：

| 列表 | 做什么 |
| :--- | :--- |
| **在线版本** | 看镜像上的可用版本；点 **下载到服务器** 拉到本机 |
| **本地安装包** | 看已下载或导入的包；可删除，或补齐 / 替换可选的源码包 |

页头会标出 **推荐版本**。需要刷新目录时用 **刷新版本列表**。

| 列（在线版本） | 说明 |
| :--- | :--- |
| **版本** | SeaTunnel 版本；推荐版本带 **推荐** 标记 |
| **状态** | 是否可下载 |
| **源码包** | 是否已下载源码，或是否支持与二进制一并下载 |
| **下载链接** | **下载到服务器**、进度，或 **已下载** |

下载对话框里可选镜像（如阿里云、华为云、Apache），并可勾选 **同时下载源码包**。源码包可选，主要用于 AI Agent 排障场景。

## 离线导入

打开 **离线导入 / 导出** → **导入**，选择 `.tar.gz`：

| 文件名 | 识别为 | 结果 |
| :--- | :--- | :--- |
| `stx-seatunnel-offline-{版本}.tar.gz` | 离线资产包 | 写入本地安装包，并按包内内容写入插件（若有） |
| `apache-seatunnel-{版本}-bin.tar.gz` | 单个官方安装包 | 只写入本地安装包，**不含**插件 |

只导入官方 bin **不会**带上连接器；插件须在有网侧先下好并打进资产包，或无网侧另行处理。

## 离线导出（资产包）

打开 **离线导入 / 导出** → **导出**。打包**不会**自动从外网拉取；本地没有的内容打不进去。

### 有网侧

1. 启动并打开能访问镜像的 STX Web UI（可用现有环境）。
2. 在本页把目标版本 **下载到服务器**（或用导入上传官方 bin）。
3. （可选）到[插件市场](./plugin-marketplace)把同版本连接器下载到本地。
4. **导出** → 选版本 → 按需勾选「包含本地插件」→ **打包并下载**。
5. 另按[离线安装](../get-started/quick-start#离线安装)准备 **STX 离线安装包**；与资产包一起拷到无网机。

CLI：`stx package offline-bundle create <version> --include-plugins --confirm`，再 `stx package offline-bundle download …`。

### 无网侧

1. 用 STX 离线安装包装好并启动 STX（`--offline`）。
2. **离线导入 / 导出** → **导入**，选中有网侧导出的资产包。
3. 本地安装包 / 插件出现在对应列表后，再走一键安装或装插件。

| 要带走的包 | 作用 |
| :--- | :--- |
| STX 离线安装包 | 在无网机安装 STX Server / Web UI |
| SeaTunnel 离线资产包 | 写入无网机 STX 的本地 `packages` / `plugins` |

### 资产包目录结构

导出文件名形如 `stx-seatunnel-offline-2.3.13.tar.gz`。解压后大致为：

```text
stx-seatunnel-offline-2.3.13/
├── MANIFEST.json                          # 格式、版本、安装包校验、插件清单
├── packages/
│   ├── apache-seatunnel-2.3.13-bin.tar.gz # 必有
│   └── apache-seatunnel-2.3.13-src.tar.gz # 可选（导出时勾选且本地已有）
└── plugins/
    └── 2.3.13/                            # 可选（导出时勾选「包含本地插件」）
        ├── connectors/                    # 连接器 JAR
        ├── metadata/                      # 插件元数据
        └── plugins/                       # 附属依赖（如 JDBC 驱动）
```

`MANIFEST.json` 中 `format` 为 `stx-seatunnel-offline-bundle/v1`。导入时由 STX 按清单写入本地仓；一般无需手解压。

## 和集群安装、升级的关系

| 场景 | 需要什么 |
| :--- | :--- |
| **一键安装 · 在线** | 若本地还没有目标版本，安装过程会按需下载 |
| **一键安装 · 离线** | **本地安装包**里必须已有目标版本（导入资产包或单个 bin） |
| **集群升级** | 升级前须备好目标版本的本地包；缺包时界面会提示前往安装包管理 |

默认节点安装目录形如 `/opt/seatunnel-{版本}`。安装与升级细节见[集群管理](../host-cluster/cluster-management)。
