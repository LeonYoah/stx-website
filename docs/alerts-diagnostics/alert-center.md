Web UI **告警与诊断** → **告警中心**（`/monitoring`）。页面右上角可切换 **告警事件** 和 **告警策略与通知**；顶部也可进入[诊断中心](./error-center)。

## 告警事件

![告警事件列表、状态筛选和时间范围](/img/screenshots/18-alert-events.png)

列表汇集平台产生的告警事件。可按状态、集群、来源和时间范围筛选，也可搜索告警名称、规则标识和摘要。点击行末操作查看事件详情、时间线与处理记录。

| 列 | 看什么 |
| :--- | :--- |
| **集群 / 来源** | 告警属于哪个集群，以及告警类别。 |
| **告警名称 / 严重级别** | 规则名称、标识和级别。 |
| **当前状态** | 触发中、已恢复或已关闭。 |
| **摘要 / 首次触发 / 最近变化** | 问题简述及发生时间。 |

告警来源分为三类：

| 来源 | 包含内容 |
| :--- | :--- |
| **平台健康** | 平台与集群运行状态相关的告警，例如节点异常、Agent 链路异常，以及集群级的「作业状态获取失败」「事件通道降级」等规则。 |
| **指标告警** | 基于内置监控指标评估触发的告警，例如 CPU、内存、FD、线程池积压等。 |
| **作业告警** | 面向具体作业的告警，例如作业运行失败、CDC 延迟过高等任务级规则。 |

**当前状态**反映告警条件或本次事件的状态；**处理进度**记录人工操作。**已接手**不等于**已恢复**。

| 操作 | 结果 |
| :--- | :--- |
| **确认** | 标记已接手，可留下备注。 |
| **静默30分钟** | 触发中且未静默时，暂时不再通知。 |
| **人工关闭** | 关闭本次事件；后续新的独立事件仍可再次告警。 |
| **前往诊断中心深度排查** | 带着告警线索继续查看错误或巡检结果。 |

## 告警策略与通知

切到 **告警策略与通知** 后，分 **告警策略**、**通知通道**、**投递记录** 三个页签。

![告警策略列表与新建入口](/img/screenshots/44-alert-policies.png)

| 页签 | 操作 |
| :--- | :--- |
| **告警策略** | 选择模板、作用集群、级别、冷却时间和通知渠道，定义何时发出告警；规则开关与阈值随策略一起配置。 |
| **通知通道** | 新建邮件通道或 Webhook，保存后测试发送。 |
| **投递记录** | 核对通知是否成功送出，查看失败原因。 |

通知路由可按告警类别（`source_type`）匹配：`platform_health`（平台健康）、`metric`（指标告警）、`job`（作业告警）。

![通知通道列表与新建入口](/img/screenshots/19-notification-channels.png)

通知通道目前提供**邮件**和 **Webhook** 两种新建入口。企业微信、钉钉或飞书机器人可按目标平台要求填写 Webhook 地址。

![投递记录列表与失败原因](/img/screenshots/45-delivery-history.png)

投递记录按策略与通道核对每次通知是否送达，可查看响应码与失败原因。需要继续查看现场时，转到[巡检与诊断报告](./diagnostic-report)。

命令行操作见 [STX CLI](../architecture/cli)。
