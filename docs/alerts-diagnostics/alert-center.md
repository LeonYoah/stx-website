Web UI **告警与诊断** → **告警中心**（`/monitoring`）。页面右上角可切换 **告警事件** 和 **规则与通知**；顶部也可进入[诊断中心](./error-center)。

## 告警事件

![告警事件列表、状态筛选和时间范围](/img/screenshots/18-alert-events.png)

列表汇集**本地进程事件**与**远程 Alertmanager** 告警。可按状态、集群、来源和时间范围筛选，也可搜索告警名称、规则标识和摘要。点击行末操作查看事件详情、时间线与处理记录。

| 列 | 看什么 |
| :--- | :--- |
| **集群 / 来源** | 告警属于哪个集群，以及来自本地进程事件还是远程 Alertmanager。 |
| **告警名称 / 严重级别** | 规则名称、标识和警告或严重级别。 |
| **当前状态** | 触发中、已恢复或已关闭。 |
| **摘要 / 首次触发 / 最近变化** | 问题简述及发生时间。 |

**当前状态**反映告警条件或本次事件的状态；**处理进度**记录人工操作。**已接手**不等于**已恢复**。

| 操作 | 结果 |
| :--- | :--- |
| **确认** | 标记已接手，可留下备注。 |
| **静默30分钟** | 触发中且未静默时，暂时不再通知。 |
| **人工关闭** | 关闭本次事件；后续新的独立事件仍可再次告警。 |
| **前往诊断中心深度排查** | 带着告警线索继续查看错误或巡检结果。 |

## 规则与通知

切到 **规则与通知** 后，依次使用 **告警规则**、**通知通道** 和 **投递记录**。

| 页面 | 操作 |
| :--- | :--- |
| **告警规则** | 按集群查看规则，调整开关、阈值和时间窗口。 |
| **通知通道** | 新建邮件通道或 Webhook，保存后测试发送。 |
| **投递记录** | 核对通知是否成功送出，查看失败原因。 |

![通知通道列表与新建入口](/img/screenshots/19-notification-channels.png)

通知通道目前提供**邮件**和 **Webhook** 两种新建入口。企业微信、钉钉或飞书机器人可按目标平台要求填写 Webhook 地址；不要把它们当作独立的通道类型。需要继续查看现场时，转到[巡检与诊断报告](./diagnostic-report)。

命令行操作见 [STX CLI](../architecture/cli)。
